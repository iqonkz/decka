## R-01. WebView на Android 10

**Что может случиться.** Системный WebView на старом телефоне давно не обновлялся: не работают современные CSS/JS, сборка Vite 8 с целью по умолчанию не запускается. Со схемой `https` WebView блокирует `ws://`. Android 9+ запрещает нешифрованный трафик по умолчанию. Иммерсивный режим на One UI может вести себя иначе, чем на чистом Android. Поддержка Android 10 в Chrome/WebView может прекратиться `[unverified: сроки]`.

**Меры.**
- Цель сборки клиента зафиксирована: `build.target: "chrome90"` (T0.3); никаких API новее без проверки наличия (`navigator.wakeLock?.`).
- `androidScheme: "http"`, `cleartext: true`, `usesCleartextTraffic="true"` (T7.1).
- Двойная защита от гашения экрана: плагин keep-awake и `FLAG_KEEP_SCREEN_ON` в `MainActivity` (T7.2).
- Иммерсивный режим восстанавливается при каждом возврате фокуса окна (T7.2).
- В README — требование обновить «Android System WebView»/Chrome из Google Play перед установкой.
- Запасной путь без APK: веб-клиент в Chrome по USB (`http://localhost:9247` — безопасный контекст).
- Ручная проверка на S9 — обязательный пункт T7.2, T9.4.

## R-02. adb на Windows

**Что может случиться.** adb не установлен или не в PATH; телефон в состоянии `unauthorized`; нет драйвера Samsung; конфликт версий adb-серверов (Android Studio, эмуляторы, scrcpy) приводит к перезапуску сервера и потере `reverse`; проброс теряется после переподключения кабеля и сна ПК; запуск adb из GUI-процесса мигает консолью.

**Меры.**
- adb не входит в поставку; путь настраивается (`usb.adbPath`), состояние `adb not found` и `unauthorized` показывается в окне настроек с понятным текстом (T7.4, T6.4).
- Цикл каждые 5 с и полный сброс списка проброшенных раз в 60 с — самовосстановление (T7.4).
- Все вызовы adb — с `CREATE_NO_WINDOW` и таймаутом 4 с.
- USB-режим выключен по умолчанию — пользователи без adb ничего не замечают.
- В README — пошаговая инструкция: отладка по USB, platform-tools, драйвер, подтверждение ключа.
- Клиент не зависит от USB: при недоступном `127.0.0.1` через 1,5 с переходит к LAN-адресам.

## R-03. Брандмауэр Windows и изоляция сети

**Что может случиться.** Windows блокирует входящие на порт 9247 (пользователь закрыл диалог или сеть помечена как «общедоступная»); роутер изолирует клиентов Wi-Fi (AP isolation, гостевая сеть); ПК в сети по кабелю, телефон в другой подсети. Симптом одинаков: телефон «не видит» ПК.

**Меры.**
- Вкладка Status показывает точную команду `netsh` для правила (профиль private) и адреса, на которых слушает агент (T6.4).
- Текст ошибки сопряжения на телефоне прямо называет Wi-Fi и кабель (T4.3).
- USB-режим как гарантированный обходной путь, не зависящий от сети.
- Раздел Troubleshooting в README: профиль сети, изоляция клиентов, проверка `http://<ip>:9247/api/health` из браузера телефона.
- Установщик правило брандмауэра сам не создаёт (потребовал бы повышения прав) — решение D-14.

## R-04. Сон и гибернация ПК

**Что может случиться.** Соединение рвётся; телефон показывает «мёртвые» кнопки; после пробуждения сокеты зависают в полуоткрытом состоянии; проброс adb пропадает; действие `sleep` выполняет гибернацию, если она включена.

**Меры.**
- Heartbeat: клиент рвёт сокет после 25 с тишины, сервер — после 30 с (PROTOCOL.md §1).
- Бесконечное переподключение с задержкой до 15 с; немедленная попытка при возврате видимости страницы (T4.2).
- Кнопки действий недоступны без связи; через 30 с — заставка `PC offline`, экран почти чёрный (T4.5, T8.3).
- Самовосстановление проброса adb ≤ 60 с (T7.4).
- Поведение `sleep` при гибернации описано в README.
- Ручная проверка — T7.5 (г).

## R-05. Батарея S9 при круглосуточной зарядке

**Что может случиться.** Литиевый аккумулятор 2018 года, постоянно на 100% и в тепле, деградирует и может вздуться. Это риск безопасности, а не удобства. Штатного ограничения заряда на прошивке S9 может не быть `[unverified]`.

**Меры.**
- Затемнение и заставка резко снижают энергопотребление и нагрев AMOLED (M8).
- Сборщик `sys` не работает без клиентов; рассылка только при изменениях — меньше пробуждений радиомодуля и процессора.
- Раздел README «Battery and burn-in notes»: питание от USB-порта ПК (слабый ток) вместо быстрой зарядки; не ставить под прямое солнце; периодически осматривать корпус; при вздутии — немедленно прекратить использование; вариант с умной розеткой по расписанию.
- Вне MVP: показ уровня и температуры батареи телефона, предупреждение о перегреве.
- Ограничение: программно ограничить заряд без root Decka не может — это честно указано в README.

## R-06. Выгорание AMOLED

**Что может случиться.** Статичная сетка кнопок за недели оставляет остаточное изображение.

**Меры.**
- Весь M8: чёрный фон, pixel shift ±4 px, затемнение, заставка с блуждающими часами, ночной режим.
- Нет постоянных ярких элементов: индикатор канала связи показывается 4 с; плашка `PC offline` сменяется заставкой через 30 с.
- Значения по умолчанию консервативны: затемнение через 60 с, заставка через 10 минут.
- Ограничение: сдвиг на 4 px замедляет, но не исключает выгорание ярких статичных иконок — указано в README; пользователю рекомендуются тёмные цвета кнопок.

## R-07. Нешифрованный трафик в локальной сети

**Что может случиться.** В недоверенной Wi-Fi-сети перехватывается токен устройства или `apiToken`; злоумышленник вызывает определённые пользователем действия или рассылает уведомления.

**Меры.**
- Ограничение ущерба архитектурой: токен устройства даёт только вызов заранее определённых действий, произвольных команд в протоколе нет (ARCHITECTURE.md §6).
- Режим «только USB» (`bind = 127.0.0.1`) — нулевая сетевая поверхность.
- Отзыв устройств и перевыпуск `apiToken`.
- Подтверждение удержанием для опасных действий; предупреждение в редакторе действий типа `launch`.
- README прямо говорит: используйте только в доверенной домашней сети или по USB; не пробрасывайте порт в интернет.
- TLS с закреплением сертификата через QR — первый кандидат после MVP (DECISIONS.md D-08).

## R-08. Свежие мажорные версии зависимостей

**Что может случиться.** TypeScript 7, Vite 8, Capacitor 8, axum 0.8, rand 0.10, enigo 0.6 — недавние версии; имена API в плане могут не совпасть с фактическими; возможна несовместимость пар (`tower-http` и `axum`).

**Меры.**
- Версии закреплены точно; автоматического обновления нет.
- Правило 3 исполнителя: сверять API с документацией установленной версии; правило 4: при невозможности — `BLOCKERS.md`, а не самостоятельная замена библиотеки.
- Запасные варианты заданы заранее для двух самых вероятных отказов (T0.1 — TypeScript, T2.4 — tower-http).
- Ядро покрыто тестами, не зависящими от Tauri и Android, — поломки локализуются быстро.
- CI на `windows-latest` (T9.3).

## R-09. Эмуляция ввода и запуск программ на Windows

**Что может случиться.** Эмулированные клавиши не доходят до окон, запущенных от администратора (UIPI), и до некоторых игр с античитом; медиаклавиши уходят не тому плееру; антивирус или SmartScreen помечают неподписанный exe, эмулирующий ввод; `launch` приложений из Microsoft Store по имени exe работает не всегда.

**Меры.**
- Ограничения перечислены в README (Troubleshooting).
- Кнопка `Test` в редакторе действий — пользователь сразу видит, работает ли действие (T6.6).
- Ошибка запуска возвращается на телефон как `ACTION_FAILED` с тостом.
- Запуск агента от администратора не предлагается (расширил бы ущерб при компрометации).
- Подпись кода — вопрос владельца (OPEN_QUESTIONS.md Q-3); без подписи в README — инструкция по SmartScreen.

## R-10. Смена IP-адреса ПК

**Что может случиться.** DHCP выдал ПК новый адрес — сохранённые на телефоне адреса не работают. mDNS (`*.local`) на Android 10 не разрешается.

**Меры.**
- QR содержит до 4 адресов ПК; клиент перебирает все (PROTOCOL.md §8).
- USB-режим от адреса не зависит.
- Повторное сканирование QR заменяет сохранённое соединение за одно действие (T4.3 п. 3).
- README рекомендует закрепить адрес ПК в роутере (DHCP reservation).
- Вне MVP: обнаружение агента через UDP-рассылку или NSD-плагин.
