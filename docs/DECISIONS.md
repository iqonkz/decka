# DECISIONS.md — журнал решений Decka

Формат: решение — причина — отвергнутые альтернативы. Решения D-01..D-06 заданы владельцем и не пересматриваются; остальные приняты архитектором.

## Заданные владельцем

| № | Решение |
|---|---|
| D-01 | Агент: Tauri 2 (Rust) + React-окно настроек, трей, автозапуск, встроенный axum (WebSocket + `POST /api/notify`) |
| D-02 | Клиент: React + TypeScript + Vite; Android через Capacitor; работает и в браузере |
| D-03 | Общие типы в `/shared` |
| D-04 | Транспорт: WebSocket по LAN и по USB через `adb reverse` |
| D-05 | Сопряжение по QR + токен |
| D-06 | Телефон отправляет только id действия; действия лежат в `actions.json` на ПК; произвольные команды от телефона — NEVER |

## Принятые архитектором

### D-07. Ядро агента — отдельный crate `decka-core` без зависимости от Tauri
**Причина:** тестируется `cargo test` без окна и WebView; headless-бинарь даёт исполнителю проверку через curl и скрипт; Tauri-оболочка остаётся тонкой.
**Альтернативы:** вся логика в `src-tauri` (нельзя тестировать сервер без запуска приложения); отдельный процесс-сервис (лишняя сложность установки).

### D-08. В MVP без TLS; трафик по LAN не шифруется
**Причина:** самоподписанный сертификат в WebView требует закрепления сертификата и нативного кода; для `wss://` на IP-адрес нет доверенного сертификата. Ущерб ограничен архитектурой (D-06), есть режим «только USB».
**Альтернативы:** TLS с отпечатком сертификата в QR (после MVP — первый приоритет); прикладное шифрование поверх WS (самодельная криптография — нет); туннель Tailscale (внешняя зависимость и аккаунт).

### D-09. Сопряжение выполняется внутри WebSocket (`pair`), а не HTTP-эндпоинтом
**Причина:** приложение Capacitor имеет origin `http://localhost`; HTTP-запрос к агенту был бы кросс-доменным и потребовал CORS. WebSocket не подчиняется CORS, а `Origin` проверяется по белому списку. HTTP API в результате вообще не отдаёт CORS-заголовков.
**Альтернативы:** `POST /api/pair` + CORS (расширяет поверхность атаки из браузера); нативный HTTP-плагин Capacitor (лишняя зависимость).

### D-10. Состояние — именованные секции; `patch` несёт секцию целиком; рассылка только при изменении
**Причина:** идея Desko; простота и идемпотентность, клиенту не нужен алгоритм слияния; секции малы (сотни байт — единицы КБ).
**Альтернативы:** JSON Patch (RFC 6902) — сложнее и не нужен при таких размерах; частичные патчи, как у Desko для позиции воспроизведения, — у Decka нет таких высокочастотных полей.

### D-11. Раскладка хранится на ПК и передаётся клиенту как секция `layout`
**Причина:** телефон — тонкий клиент; одно место редактирования; смена раскладки применяется мгновенно на всех устройствах.
**Альтернативы:** раскладка на телефоне (редактирование пальцем на маленьком экране, рассинхронизация); отдельная раскладка на каждое устройство (после MVP).

### D-12. Контракт TS ↔ Rust держится на общих фикстурах, без генерации кода
**Причина:** генераторы (`ts-rs`, `typeshare`, `schemars`) добавляют инструменты и неочевидные расхождения; фикстуры проверяются с обеих сторон: ajv по схеме в TS и round-trip serde в Rust.
**Альтернативы:** генерация TS из Rust; генерация обоих из JSON Schema.

### D-13. Пять типов действий в MVP: `hotkey`, `media`, `launch`, `open_url`, `system`
**Причина:** покрывают сценарии Stream Deck начального уровня (набор близок к ODeck); каждый тип имеет узкую проверяемую семантику; ни один не исполняет строку через shell.
**Альтернативы:** тип «shell-команда» (инъекции и неоднозначные кавычки — пользователь может вызвать `powershell.exe` через `launch` осознанно); макросы и мульти-действия (после MVP); плагины, как у Macro Deck (после MVP).

### D-14. Привязка по умолчанию `0.0.0.0`; режим «только USB» — `127.0.0.1`; правило брандмауэра установщик не создаёт
**Причина:** Wi-Fi должен работать сразу; создание правила требует прав администратора при установке; штатный диалог Windows + команда в окне настроек достаточно.
**Альтернативы:** по умолчанию `127.0.0.1` (большинство пользователей не смогут подключиться); привязка только к частным адресам (ломается при смене сети); установщик с повышением прав.

### D-15. Порт по умолчанию 9247
**Причина:** не используется распространёнными инструментами разработчика (3000, 5173, 8080, 8787, 4455 — заняты привычными сервисами); выше 1024; настраивается.
**Альтернативы:** 7777 (как у Desko — возможен конфликт при параллельной установке), 8191.

### D-16. mDNS в MVP нет
**Причина:** Android до 12 не разрешает `.local` в браузере и WebView (отмечено в README Desko); целевое устройство — Android 10. Проблему смены IP решают несколько адресов в QR и USB-режим.
**Альтернативы:** NSD через нативный плагин; UDP-обнаружение (после MVP).

### D-17. Веб-режим — манифест без service worker
**Причина:** по `http://<LAN-IP>` service worker недоступен (небезопасный контекст); офлайн-кэш бессмысленен — без агента клиент бесполезен; клиент всегда отдаётся агентом той же версии.
**Альтернативы:** `vite-plugin-pwa` (лишняя зависимость без пользы).

### D-18. Клиент без библиотек состояния и UI; обычный CSS
**Причина:** состояние — один объект с пятью секциями; `useSyncExternalStore` достаточно; меньше зависимостей — меньше размер для старого WebView и меньше риск несовместимости.
**Альтернативы:** Zustand, Redux, Tailwind, готовые UI-киты.

### D-19. Иконки: фиксированный набор из 60 иконок Lucide и emoji
**Причина:** лицензия ISC; именованные импорты дают маленькую сборку; телефон не загружает файлы с ПК.
**Альтернативы:** весь набор Lucide (сборка на мегабайты); пользовательские PNG (после MVP: потребует раздачи файлов и лимитов).

### D-20. Переменные и статусы живут только в памяти
**Причина:** это отражение текущего состояния внешнего мира; после рестарта источники пришлют его заново; нет миграций и порчи файлов.
**Альтернативы:** сохранение на диск.

### D-21. Токены устройств хранятся как SHA-256; `apiToken` — открытым текстом в `config.json`
**Причина:** токен устройства — 256 бит случайности, быстрый хэш достаточен, показывать его не нужно. `apiToken` пользователь должен копировать в скрипты; файл защищён правами профиля Windows.
**Альтернативы:** Windows Credential Manager (усложняет headless и тесты); argon2 (не нужен для высокоэнтропийных токенов).

### D-22. Клиент шлёт `actionId`, а не идентификатор кнопки
**Причина:** буквальное следование D-06; сервер не зависит от раскладки при исполнении.
**Альтернативы:** слать `itemId` и находить действие по раскладке (скрыло бы `actionId` от клиента, но противоречит формулировке владельца и усложняет гонки при смене раскладки).

### D-23. Эмуляция клавиш — crate `enigo` в выделенном потоке
**Причина:** MIT, покрывает клавиши и медиаклавиши одним API; выделенный поток снимает вопрос потокобезопасности.
**Альтернативы:** прямой `SendInput` через `windows-rs` (больше небезопасного кода); `rdev`.

### D-24. adb не входит в поставку
**Причина:** условия распространения Android SDK Platform-Tools ограничивают перераспространение `[unverified: точная формулировка]`; пользователи USB-режима — разработчики, у которых adb обычно есть.
**Альтернативы:** автозагрузка platform-tools (сетевой доступ установщика, вопросы лицензии); собственная реализация протокола ADB (несоразмерно).

### D-25. npm workspaces; пакет `shared` потребляется исходниками
**Причина:** не нужен шаг сборки и дополнительный менеджер пакетов; Vite транспилирует связанные пакеты workspace.
**Альтернативы:** pnpm/turborepo; сборка `shared` в `dist`.

### D-26. Проверка качества — `tsc --noEmit`, vitest, cargo test; без ESLint
**Причина:** TypeScript 7 — новая реализация компилятора; совместимость линтеров, завязанных на API компилятора, не проверена `[unverified]`.
**Альтернативы:** ESLint + typescript-eslint; Biome (версия не проверялась).

### D-27. Интерфейс на английском, без локализации в MVP
**Причина:** open source для GitHub; локализация — отдельная работа.
**Альтернативы:** русский интерфейс; i18n с первого дня. Язык документации — вопрос владельца (OPEN_QUESTIONS.md Q-5).
**Пересмотрено D-43.**

### D-43. Русский язык интерфейса (2026-11-15, пересматривает D-27)
**Причина:** решение владельца. Два языка, свой модуль словарей в `shared` (≈ 100 строк кода): полнота перевода проверяется компилятором TypeScript, множественное число — встроенный `Intl.PluralRules`. Настройка одна на ПК (`display.language`) и доходит до телефона с раскладкой; `auto` по умолчанию, чтобы русская Windows сразу давала русский интерфейс.
**Альтернативы:** i18next / react-intl (лишние зависимости ради двух языков); отдельные настройки языка на телефоне и ПК (лишний параметр); перевод сообщений проверки агента сейчас (их много в Rust и TS, видны редко — отложено).

### D-28. Защита экрана — CSS-слой, без управления аппаратной яркостью
**Причина:** на AMOLED чёрные пиксели не светятся, полупрозрачный чёрный слой снижает яркость и износ без нативных плагинов и разрешений.
**Альтернативы:** плагин яркости экрана; выключение экрана с пробуждением по датчику приближения (после MVP).

### D-29. Автообновления в MVP нет
**Причина:** tauri-updater требует ключей подписи и хостинга манифеста — решения владельца.
**Альтернативы:** tauri-plugin-updater + GitHub Releases (после MVP).

### D-36. Четыре темы на одной геометрии; визуальная спецификация в DESIGN.md
**Причина:** решение владельца 2026-11-15: внешний вид — первое, за что пользователи полюбят продукт. Одна геометрия (квадратные клавиши, зазор 4%) — раскладка не зависит от темы, превью в редакторе точное, тестировать проще. Тема хранится в раскладке на ПК и одинакова на всех устройствах.
**Альтернативы:** тема на каждом телефоне отдельно (раскладка общая, а тема — нет: путаница в превью); разная геометрия для тем (умножает варианты раскладки).

### D-37. Общий пакет `@decka/ui` для телефона и окна настроек
**Причина:** редактор «что видишь — то и получишь» должен рисовать ровно те же компоненты в той же теме. Пересматривает часть D-18: клиент по-прежнему без UI-библиотек, но компоненты вынесены в свой пакет workspace.
**Альтернативы:** отдельный рендер превью в окне настроек (расхождения с телефоном); iframe с клиентом (сложная связь с редактором, нет перетаскивания).

### D-38. Перетаскивание в редакторе раскладки (пересматривает D-30)
**Причина:** отзыв владельца — текущий редактор сложен. Реализация на pointer-событиях без библиотек; ячейки фиксированы, поэтому граничных случаев мало.
**Альтернативы:** оставить клики и числовые поля (сложно для новых пользователей); dnd-библиотека (лишняя зависимость).

**Дополнение 2026-11-15 (M14):** реализация T13.9 ушла на HTML5 drag-and-drop, который в окне Tauri на Windows перехватывается WebView2 (по умолчанию `dragDropEnabled: true`), — владелец не смог перетащить ни одной клавиши. Возврат к pointer-событиям обязателен. `dragDropEnabled` остаётся `true`: он нужен для броска `.exe`/`.lnk` из Проводника (DESIGN.md §4.5). Любая задача с перетаскиванием принимается только после проверки в настоящем окне (`npm run tauri dev`), не в Chrome.

### D-41. Кнопка за два клика, автосохранение, онбординг (M14)
**Причина:** отзыв владельца — создание кнопки сложное, нет онбординга. Основной путь — клик по пустой клетке и выбор из единого списка (программы, готовые действия, свои действия, виджеты); имя, иконка и действие заполняются сами. Автосохранение как в программах аппаратных дек: телефон показывает результат сразу, а отмена `Ctrl+Z` защищает от ошибок лучше, чем ручное сохранение.
**Альтернативы:** только палитра с перетаскиванием (не находится без подсказки); мастер «новая кнопка» из нескольких шагов (медленнее); ручное сохранение (лишний шаг и потерянные правки).

### D-42. «Большая иконка» и упрощение окна (M14, 2026-11-15)
**Причина:** владелец хочет красивые клавиши-иконки без отступов с подписью по выбору и более понятное окно. Стиль клавиш — глобальная настройка с переопределением на кнопке (одна галочка покрывает 90% случаев). Иконки программ увеличены до 256 px, иначе во всю клавишу они размыты; предел секции `icons` поднят до 131 072 символов на иконку (≤ 200 иконок; полное состояние остаётся в пределах единиц мегабайт по LAN/USB). Окно сведено к 4 разделам; второстепенное — в контекстные меню и `More options`.
**Альтернативы:** только глобальный стиль (нельзя смешивать плитки и обычные клавиши); растягивать 96-px иконки (мыло); отдельный режим «простой/эксперт» (две версии интерфейса, вдвое больше тестов).

### D-44. Единая версия, CHANGELOG и проверка обновлений (2026-11-15)
**Причина:** владелец попросил контроль версий. Один номер SemVer на агент, клиент и APK — пользователю проще сверить «телефон и ПК одной версии». Скрипт поднятия версии исключает расхождение номеров в шести файлах. Проверка обновлений через публичный API GitHub Releases бесплатна и не требует ключей подписи; скачивание и установку делает пользователь, поэтому не нужен механизм подписанных обновлений (Q-8).
**Альтернативы:** раздельные версии агента и клиента (путаница); `tauri-plugin-updater` (нужны ключи подписи и манифест — отложено); проверка с телефона (у телефона может не быть интернета, он ходит только к ПК).

### D-45. Книжная ориентация — одна на раскладку, переход через `rotateLayout` (2026-11-15)
**Причина:** владелец попросил книжную ориентацию. Панель стоит на столе в одном положении, поэтому ориентация — настройка раскладки, а не датчик. Одна сетка на все страницы сохраняет простую модель данных; поворот — явная операция с превью и отменой, переполнение уходит на новую страницу без потери кнопок.
**Альтернативы:** две раскладки (для каждой ориентации) — вдвое больше работы владельцу; автоповорот по датчику с транспонированием на лету — виджеты и порядок кнопок «прыгают»; автоматическая перекомпоновка «по порядку чтения» — кнопки теряют привычные места.

### D-46. Каталог готовых кнопок и наборы как данные (M15, 2026-11-16)
**Причина:** сравнение с аппаратными деками и Macro Deck: главное отличие — готовые действия по категориям, наборы связанных кнопок и кнопки, которые показывают состояние. Каталог и наборы — JSON в `shared`, не код: их легко дополнять, проверять схемой и переводить; состояние идёт через уже существующие `vars` и `bind`, поэтому телефону ничего нового понимать не нужно, кроме новых виджетов. Ползунок громкости шлёт обычные `press` (S19), чтобы не ослаблять правило «только actionId».
**Альтернативы:** плагины по образцу аппаратных дек (свой SDK, процессы плагинов, безопасность — слишком рано); значение громкости с телефона (нарушает главное правило безопасности); профили целиком вместо наборов (меньше гибкости, наборы покрывают «стартовые профили» через мастер).

### D-47. Погода — Open-Meteo через агент; OBS — локально; облачные сервисы позже (M15, 2026-11-16)
**Причина:** Open-Meteo бесплатен и без ключа (условия — некоммерческое использование, данные CC BY 4.0 с указанием источника); запрос делает агент, как и проверку обновлений, телефон остаётся без интернета. OBS даёт стримерам главное (запись, эфир, сцены, микрофон) через локальный obs-websocket без учётных записей. Twitch, YouTube, Discord требуют регистрации приложения разработчика, OAuth и хранения токенов на ПК — это отдельный этап после того, как владелец решит, нужен ли он (OPEN_QUESTIONS Q-9).
**Альтернативы:** погода через OpenWeatherMap (нужен ключ); погода с телефона по геолокации (интернет и разрешение на телефоне, нарушает модель «телефон ходит только к ПК»); Streamer.bot/Touch Portal-подобная шина событий (избыточно для v1).

### D-49. Список владельца 2026-11-19 (M17)
**Причина:** отзыв владельца. По пунктам (подробно — DATA_MODEL §10):
- **Память:** окно настроек уничтожается при закрытии, а не скрывается. Замер: 210 из 232 МБ занимал WebView2 скрытого окна.
- **Перелистывание:** позиция меняется прямо в DOM, без React на каждом движении пальца.
- **Системные сочетания** выбираются переключателями, потому что Windows забирает их раньше окна.
- **Полоса приложения** вместо вопроса «Добавить кнопки?» — по образцу Touch Bar. Раскладка не трогается, режим для каждого приложения хранится на телефоне, так что на ПК заходить не нужно.
- **Уведомления Windows** — через `UserNotificationListener`, если он доступен непакетному exe. Открыть программу — по AUMID на стороне агента.
- **Заряд** — системное свойство Bluetooth-устройств Windows.
- **Почта** — IMAP STATUS по паролю приложения.
- **Переворот** — локальная настройка телефона и блокировка ориентации по датчику.

**Альтернативы:**
- Скрытие окна с `MemoryUsageTargetLevel` WebView2: экономит меньше, процессы остаются.
- Перехват клавиатуры низкоуровневым хуком при записи сочетания: глобальный перехват ввода ради редкой операции, а `Win+L` и `Ctrl+Alt+Del` всё равно недоступны.
- Полоса как новая страница или автосоздание страницы: портит настроенное — возражение владельца.
- Sparse package ради уведомлений: нужна подпись, а Q-3 — без подписи.
- Чтение `wpndatabase.db`: недокументировано, нужна новая зависимость SQLite.
- Gmail API или Microsoft Graph через OAuth: регистрация приложений, отложено как Q-9.
- Outlook через COM: только классический Outlook, тяжело.
- Поворот по датчику во все четыре стороны: смена альбомной/книжной перестраивает сетку, а владелец просил только переворот.

### D-48. Лимиты Claude Code / Codex и разрешения с телефона — из локальных данных и официальных хуков (M16, 2026-11-17)
**Причина:** просьба владельца по образцу PhoneBox (MIT; взяты только идеи, код не копируется — строка в NOTICE).
- **Лимиты Claude** приходят в документированном JSON строки статуса Claude Code (`rate_limits.five_hour/seven_day`). Командой строки статуса служит встроенный в Windows `curl.exe`, поэтому отдельный исполняемый файл не нужен.
- **Разрешения** — документированный хук `PermissionRequest` типа `http`: Claude Code сам ждёт ответа агента. Пустой ответ возвращает вопрос в терминал, так что при любой неполадке ничего не разрешается молча.
- **Лимиты Codex** Codex пишет в свои `rollout-*.jsonl` (`rate_limits`; формат проверен на ПК владельца 2026-11-17).
- **Ответ телефона** — одноразовый `reqId` и выбор (S20). Это не команда, поэтому правило «только actionId» не нарушается.

**Альтернативы:**
- Недокументированный OAuth-эндпоинт использования с токеном из `.credentials.json`: чтение секретов, хрупкость, исходящий запрос с токеном. Отвергнуто.
- Отдельный бинарь-посредник для statusline и хука: лишняя сборка и установка.
- «Разрешить всегда» с телефона: правило записалось бы в настройки Claude с телефона. Отложено.
- Разрешения для Codex: нет проверенного механизма хуков. Отложено.

### D-39. Всплывающие группы через страницы с `popup: true`
**Причина:** владелец хочет, чтобы по нажатию появлялись релевантные кнопки (как раскрывающиеся группы на сенсорной панели ноутбука и папки на аппаратных деках). Переиспользуется модель страниц: редактор, валидация и шаблоны работают без нового типа данных. Сочетание `actionId + popup` даёт сценарий «открыть приложение и показать его команды».
**Альтернативы:** вложенный массив кнопок внутри кнопки (второй редактор и валидатор); долгое нажатие для группы (неочевидно, конфликтует с `confirm`).

### D-40. Тема Glass — интерпретация средствами WebView с автоматическим упрощением
**Причина:** системное стекло Apple в WebView недоступно; размытие, насыщение, преломление SVG-фильтром и зеркальная кромка дают близкое ощущение. На слабых GPU (S9) эффект дорогой — замер частоты кадров и режим `reduced`. Поддержка `backdrop-filter: url()` в установленном WebView `[unverified]` — проверяется прототипом в T13.5 до основной работы.
**Альтернативы:** нативный слой Android (RenderEffect с API 31 — не работает на Android 10); статичная картинка стекла (не реагирует на фон).

### D-35. Иконки программ извлекаются из exe на ПК, а не скачиваются набором
**Причина:** владелец попросил иконки 500 популярных программ (2026-11-14). Извлечение системной иконки покрывает любую установленную программу, работает без сети, не раздувает репозиторий и не требует распространять логотипы — товарные знаки, которые нельзя выкладывать в MIT-репозиторий без разрешения правообладателей. Иконки доставляются телефону секцией `icons` (data URL), без отдельного HTTP-эндпоинта: `<img>` в WebView не умеет передавать заголовок `Authorization`.
**Альтернативы:** набор брендовых иконок (например, Simple Icons, CC0 на файлы, но с оговорками о товарных знаках; не покрывает рабочие утилиты); загрузка иконок из интернета по имени программы (сеть, приватность, несоответствие версий); HTTP-эндпоинт с токеном в query (токен в URL — в логах).

### D-32. Контекстные страницы: переключение решает клиент, агент только сообщает активное приложение
**Причина:** решение владельца 2026-11-14 (аналог Smart Profiles у Stream Deck). Клиент знает о касаниях и текущей странице, поэтому может не переключать страницу из-под пальца; агент остаётся источником фактов. Активное окно опрашивается каждые 250 мс со стабилизацией 700 мс — это гасит мигание при щелчке по панели задач и проще хуков `SetWinEventHook`.
**Альтернативы:** переключение на агенте (не знает о касаниях, все устройства переключались бы одновременно); хук WinEvent (нужен цикл сообщений в отдельном потоке); передача заголовка окна (приватность, S16).

### D-33. Шаблоны страниц — данные в `shared/templates`, применяются агентом
**Причина:** одна реализация слияния в Rust, атомарное сохранение обоих файлов; шаблоны проверяются теми же схемами и тестами.
**Альтернативы:** шаблоны в окне настроек (дублирование логики слияния); магазин шаблонов (вне объёма).

### D-34. «Сейчас играет» через системную медиасессию Windows (GSMTC)
**Причина:** один API покрывает Spotify, браузеры и большинство плееров без интеграций с каждым сервисом. Опрос раз в 1 с, рассылка только при смене трека/состояния/перемотке; ход позиции считает клиент.
**Альтернативы:** API Spotify (OAuth, только один сервис); события WinRT (сложнее и не нужны при опросе раз в секунду).
**Дополнение (2026-11-14):** обложки источников бывают крупнее лимита (Spotify ≈ 176 КБ PNG), поэтому агент уменьшает их до 192 px JPEG средствами `Windows.Graphics.Imaging` (T11.4b). Альтернативы: crate `image` (лишняя зависимость при наличии системного API); поднять лимит (тяжёлые патчи на каждую смену трека).

### D-31. Сетка настраивается (3..8 × 2..5), по умолчанию 7×4; без плашек, клавиши с тонкой обводкой
**Причина:** отзыв владельца после проверки на телефоне (2026-11-14): 5×3 даёт слишком крупные кнопки, серые плашки занимают место. Протокол не версионируется: v1 ещё не выпускалась, а прежняя 5×3 остаётся допустимой.
**Альтернативы:** фиксированная 7×4 (не подойдёт телефонам с другим соотношением сторон); автоподбор сетки по размеру экрана (раскладка общая для всех устройств и задаётся на ПК, поэтому размер — явная настройка).

### D-30. Редактор раскладки без drag-and-drop
**Причина:** сетка 5×3 мала; клик по ячейке и числовые поля однозначны и укладываются в задачу на 2 часа.
**Альтернативы:** dnd-библиотека (зависимость и много граничных случаев).
