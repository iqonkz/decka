# DECISIONS.md — журнал решений Decka

Формат: решение — причина — отвергнутые альтернативы. Решения D-01..D-06 заданы владельцем и не пересматриваются; остальные приняты архитектором.

## Заданные владельцем

| № | Решение |
|---|---|
| D-01 | Агент: Tauri 2 (Rust) + React-окно настроек, трей, автозапуск, встроенный axum (WebSocket + `POST /api/notify`) |
| D-02 | Клиент: React + TypeScript + Vite; Android через Capacitor; работает и в браузере |
| D-03 | Общие типы в `/shared` |
| D-04 | Транспорт: WebSocket по LAN и по USB через `adb reverse` |
| D-05 | Сопряжение по QR + токен |
| D-06 | Телефон отправляет только id действия; действия лежат в `actions.json` на ПК; произвольные команды от телефона — NEVER |

## Принятые архитектором

### D-07. Ядро агента — отдельный crate `decka-core` без зависимости от Tauri
**Причина:** тестируется `cargo test` без окна и WebView; headless-бинарь даёт исполнителю проверку через curl и скрипт; Tauri-оболочка остаётся тонкой.
**Альтернативы:** вся логика в `src-tauri` (нельзя тестировать сервер без запуска приложения); отдельный процесс-сервис (лишняя сложность установки).

### D-08. В MVP без TLS; трафик по LAN не шифруется
**Причина:** самоподписанный сертификат в WebView требует закрепления сертификата и нативного кода; для `wss://` на IP-адрес нет доверенного сертификата. Ущерб ограничен архитектурой (D-06), есть режим «только USB».
**Альтернативы:** TLS с отпечатком сертификата в QR (после MVP — первый приоритет); прикладное шифрование поверх WS (самодельная криптография — нет); туннель Tailscale (внешняя зависимость и аккаунт).

### D-09. Сопряжение выполняется внутри WebSocket (`pair`), а не HTTP-эндпоинтом
**Причина:** приложение Capacitor имеет origin `http://localhost`; HTTP-запрос к агенту был бы кросс-доменным и потребовал CORS. WebSocket не подчиняется CORS, а `Origin` проверяется по белому списку. HTTP API в результате вообще не отдаёт CORS-заголовков.
**Альтернативы:** `POST /api/pair` + CORS (расширяет поверхность атаки из браузера); нативный HTTP-плагин Capacitor (лишняя зависимость).

### D-10. Состояние — именованные секции; `patch` несёт секцию целиком; рассылка только при изменении
**Причина:** идея Desko; простота и идемпотентность, клиенту не нужен алгоритм слияния; секции малы (сотни байт — единицы КБ).
**Альтернативы:** JSON Patch (RFC 6902) — сложнее и не нужен при таких размерах; частичные патчи, как у Desko для позиции воспроизведения, — у Decka нет таких высокочастотных полей.

### D-11. Раскладка хранится на ПК и передаётся клиенту как секция `layout`
**Причина:** телефон — тонкий клиент; одно место редактирования; смена раскладки применяется мгновенно на всех устройствах.
**Альтернативы:** раскладка на телефоне (редактирование пальцем на маленьком экране, рассинхронизация); отдельная раскладка на каждое устройство (после MVP).

### D-12. Контракт TS ↔ Rust держится на общих фикстурах, без генерации кода
**Причина:** генераторы (`ts-rs`, `typeshare`, `schemars`) добавляют инструменты и неочевидные расхождения; фикстуры проверяются с обеих сторон: ajv по схеме в TS и round-trip serde в Rust.
**Альтернативы:** генерация TS из Rust; генерация обоих из JSON Schema.

### D-13. Пять типов действий в MVP: `hotkey`, `media`, `launch`, `open_url`, `system`
**Причина:** покрывают сценарии Stream Deck начального уровня (набор близок к ODeck); каждый тип имеет узкую проверяемую семантику; ни один не исполняет строку через shell.
**Альтернативы:** тип «shell-команда» (инъекции и неоднозначные кавычки — пользователь может вызвать `powershell.exe` через `launch` осознанно); макросы и мульти-действия (после MVP); плагины, как у Macro Deck (после MVP).

### D-14. Привязка по умолчанию `0.0.0.0`; режим «только USB» — `127.0.0.1`; правило брандмауэра установщик не создаёт
**Причина:** Wi-Fi должен работать сразу; создание правила требует прав администратора при установке; штатный диалог Windows + команда в окне настроек достаточно.
**Альтернативы:** по умолчанию `127.0.0.1` (большинство пользователей не смогут подключиться); привязка только к частным адресам (ломается при смене сети); установщик с повышением прав.

### D-15. Порт по умолчанию 9247
**Причина:** не используется распространёнными инструментами разработчика (3000, 5173, 8080, 8787, 4455 — заняты привычными сервисами); выше 1024; настраивается.
**Альтернативы:** 7777 (как у Desko — возможен конфликт при параллельной установке), 8191.

### D-16. mDNS в MVP нет
**Причина:** Android до 12 не разрешает `.local` в браузере и WebView (отмечено в README Desko); целевое устройство — Android 10. Проблему смены IP решают несколько адресов в QR и USB-режим.
**Альтернативы:** NSD через нативный плагин; UDP-обнаружение (после MVP).

### D-17. Веб-режим — манифест без service worker
**Причина:** по `http://<LAN-IP>` service worker недоступен (небезопасный контекст); офлайн-кэш бессмысленен — без агента клиент бесполезен; клиент всегда отдаётся агентом той же версии.
**Альтернативы:** `vite-plugin-pwa` (лишняя зависимость без пользы).

### D-18. Клиент без библиотек состояния и UI; обычный CSS
**Причина:** состояние — один объект с пятью секциями; `useSyncExternalStore` достаточно; меньше зависимостей — меньше размер для старого WebView и меньше риск несовместимости.
**Альтернативы:** Zustand, Redux, Tailwind, готовые UI-киты.

### D-19. Иконки: фиксированный набор из 60 иконок Lucide и emoji
**Причина:** лицензия ISC; именованные импорты дают маленькую сборку; телефон не загружает файлы с ПК.
**Альтернативы:** весь набор Lucide (сборка на мегабайты); пользовательские PNG (после MVP: потребует раздачи файлов и лимитов).

### D-20. Переменные и статусы живут только в памяти
**Причина:** это отражение текущего состояния внешнего мира; после рестарта источники пришлют его заново; нет миграций и порчи файлов.
**Альтернативы:** сохранение на диск.

### D-21. Токены устройств хранятся как SHA-256; `apiToken` — открытым текстом в `config.json`
**Причина:** токен устройства — 256 бит случайности, быстрый хэш достаточен, показывать его не нужно. `apiToken` пользователь должен копировать в скрипты; файл защищён правами профиля Windows.
**Альтернативы:** Windows Credential Manager (усложняет headless и тесты); argon2 (не нужен для высокоэнтропийных токенов).

### D-22. Клиент шлёт `actionId`, а не идентификатор кнопки
**Причина:** буквальное следование D-06; сервер не зависит от раскладки при исполнении.
**Альтернативы:** слать `itemId` и находить действие по раскладке (скрыло бы `actionId` от клиента, но противоречит формулировке владельца и усложняет гонки при смене раскладки).

### D-23. Эмуляция клавиш — crate `enigo` в выделенном потоке
**Причина:** MIT, покрывает клавиши и медиаклавиши одним API; выделенный поток снимает вопрос потокобезопасности.
**Альтернативы:** прямой `SendInput` через `windows-rs` (больше небезопасного кода); `rdev`.

### D-24. adb не входит в поставку
**Причина:** условия распространения Android SDK Platform-Tools ограничивают перераспространение `[unverified: точная формулировка]`; пользователи USB-режима — разработчики, у которых adb обычно есть.
**Альтернативы:** автозагрузка platform-tools (сетевой доступ установщика, вопросы лицензии); собственная реализация протокола ADB (несоразмерно).

### D-25. npm workspaces; пакет `shared` потребляется исходниками
**Причина:** не нужен шаг сборки и дополнительный менеджер пакетов; Vite транспилирует связанные пакеты workspace.
**Альтернативы:** pnpm/turborepo; сборка `shared` в `dist`.

### D-26. Проверка качества — `tsc --noEmit`, vitest, cargo test; без ESLint
**Причина:** TypeScript 7 — новая реализация компилятора; совместимость линтеров, завязанных на API компилятора, не проверена `[unverified]`.
**Альтернативы:** ESLint + typescript-eslint; Biome (версия не проверялась).

### D-27. Интерфейс на английском, без локализации в MVP
**Причина:** open source для GitHub; локализация — отдельная работа.
**Альтернативы:** русский интерфейс; i18n с первого дня. Язык документации — вопрос владельца (OPEN_QUESTIONS.md Q-5).

### D-28. Защита экрана — CSS-слой, без управления аппаратной яркостью
**Причина:** на AMOLED чёрные пиксели не светятся, полупрозрачный чёрный слой снижает яркость и износ без нативных плагинов и разрешений.
**Альтернативы:** плагин яркости экрана; выключение экрана с пробуждением по датчику приближения (после MVP).

### D-29. Автообновления в MVP нет
**Причина:** tauri-updater требует ключей подписи и хостинга манифеста — решения владельца.
**Альтернативы:** tauri-plugin-updater + GitHub Releases (после MVP).

### D-32. Контекстные страницы: переключение решает клиент, агент только сообщает активное приложение
**Причина:** решение владельца 2026-11-14 (аналог Smart Profiles у Stream Deck). Клиент знает о касаниях и текущей странице, поэтому может не переключать страницу из-под пальца; агент остаётся источником фактов. Активное окно опрашивается каждые 250 мс со стабилизацией 700 мс — это гасит мигание при щелчке по панели задач и проще хуков `SetWinEventHook`.
**Альтернативы:** переключение на агенте (не знает о касаниях, все устройства переключались бы одновременно); хук WinEvent (нужен цикл сообщений в отдельном потоке); передача заголовка окна (приватность, S16).

### D-33. Шаблоны страниц — данные в `shared/templates`, применяются агентом
**Причина:** одна реализация слияния в Rust, атомарное сохранение обоих файлов; шаблоны проверяются теми же схемами и тестами.
**Альтернативы:** шаблоны в окне настроек (дублирование логики слияния); магазин шаблонов (вне объёма).

### D-34. «Сейчас играет» через системную медиасессию Windows (GSMTC)
**Причина:** один API покрывает Spotify, браузеры и большинство плееров без интеграций с каждым сервисом. Опрос раз в 1 с, рассылка только при смене трека/состояния/перемотке; ход позиции считает клиент.
**Альтернативы:** API Spotify (OAuth, только один сервис); события WinRT (сложнее и не нужны при опросе раз в секунду).

### D-31. Сетка настраивается (3..8 × 2..5), по умолчанию 7×4; без плашек, клавиши с тонкой обводкой
**Причина:** отзыв владельца после проверки на телефоне (2026-11-14): 5×3 даёт слишком крупные кнопки, серые плашки занимают место. Протокол не версионируется: v1 ещё не выпускалась, а прежняя 5×3 остаётся допустимой.
**Альтернативы:** фиксированная 7×4 (не подойдёт телефонам с другим соотношением сторон); автоподбор сетки по размеру экрана (раскладка общая для всех устройств и задаётся на ПК, поэтому размер — явная настройка).

### D-30. Редактор раскладки без drag-and-drop
**Причина:** сетка 5×3 мала; клик по ячейке и числовые поля однозначны и укладываются в задачу на 2 часа.
**Альтернативы:** dnd-библиотека (зависимость и много граничных случаев).
